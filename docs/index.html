How it works

One node. Many VS Code windows.

A small Rust node runs on one Mac. Every VS Code window with the extension connects to it, gets a name (its "app"), and exposes Agent Bridge tools to Copilot Chat. Requests travel through the node over TLS and land as notifications in the target window.

Ask

In any window, ask Copilot to consult another app. It calls bridge_send_request with the question, logs and context.

Notify

The target window shows Request from … with Accept, View and Reject. Or it is accepted automatically in unattended mode.

Solve

On accept, a new agent-mode chat opens with the request and works on that workspace's own code.

Reply

The agent finishes with bridge_send_reply. The asking agent receives it, either by waiting or as a notification.

Features

Built for real cross-app work.

Frontends asking backends, services consulting shared libraries, or a build machine helping your laptop. Each agent stays in the codebase it knows best.

💬

Requests and replies

Send questions, logs, stack traces and change requests to another app's agent and get a full answer back.

🔔

You stay in control

Every request shows up as a notification with Accept, View and Reject. View opens the full content before anything runs.

🤖

Unattended mode

Auto-accept requests from trusted apps and process them one at a time, so a VS Code window can work on its own.

🔑

Per-machine tokens

Create one token per computer from the node dashboard. Revoke it at any time and that machine disconnects immediately.

🛡️

Pinned TLS

Traffic between machines is encrypted. Clients only trust your node's certificate, whose fingerprint is embedded in the token.

🧩

Native Copilot tools

The extension registers an MCP server automatically. No mcp.json edits: the tools appear in Copilot Chat.

📬

Never miss a message

History is stored on the node. Requests that arrive while a window is closed are delivered when it reconnects.

📊

Beautiful dashboard

See linked machines, connected apps and node addresses. The dashboard is only reachable from the node's own Mac.

⚡

Tiny and fast

A single signed Rust binary. Runs as a login service and uses almost no memory or CPU.

🔌

MCP endpoint for any AI app

The node is itself an MCP server at /mcp. Clients with MCP background tasks, like the DAFO Swarm chat, get an instant "queued" answer and the reply later, in the conversation that asked.

✖️

Cancel anytime

The sender can withdraw a request; VS Code is told it is no longer needed and drops it from the unattended queue.

🧩

Open standard

Built on the Model Context Protocol and its tasks extension, so other MCP clients work the same way.

Install

Up and running in five minutes.

Install the node on one Mac (it can also be one of your development machines), then install the extension on every machine whose VS Code windows should talk to each other.

1 Install the node on one Mac

  1. Download DAFO-Agent-Bridge-macOS.dmg and open it.
  2. Drag DAFO Agent Bridge to Applications, then open it.
  3. Click Install and confirm the ports. The suggested values are 7878 for other machines and 7879 for the local dashboard.
  4. The node starts in the background, starts again at every login, and opens its dashboard in your browser.

Open the app again at any time to reach the dashboard or uninstall the node. If macOS asks whether to accept incoming connections, choose Allow so other machines can reach it.

2 Create a token for each machine

In the dashboard, type a machine name and click Create token. Copy the token: it is shown only once. The dashboard also lists the node addresses (IP:port) other machines should use.

The node's own Mac is linked automatically during installation.

3 Install the VS Code extension

Download dafo-agent-bridge-vscode.vsix, then in VS Code open the Extensions view, click ⋯ → Install from VSIX… and choose the file. Or run:

code --install-extension dafo-agent-bridge-vscode.vsix

The extension already includes the Agent Bridge binary for macOS and Linux (x64/arm64), including Remote-SSH, WSL and dev containers. Nothing else to install.

4 Link and name each window

  1. Click Agent Bridge: Link in the status bar.
  2. Enter the node address, e.g. 10.8.0.5:7878, and paste the token.
  3. Name the app for this workspace. The folder name is suggested, e.g. billing-api.
  4. When Copilot asks to trust the DAFO Agent Bridge MCP server, allow it.

5 Ask another app

In Copilot Chat (agent mode), just ask:

Ask billing-api how invoices are validated before they are stored,
and wait for the answer.

The other window receives the request, its agent investigates its own code, and the answer comes back to your chat.

Unattended mode

Let a window work on its own.

Run Agent Bridge: Toggle Auto-Accept in a workspace. Incoming requests are accepted automatically, opened in a new agent-mode chat and processed one at a time. The status bar shows a robot icon while it is on.

Settings

agentBridge.autoAccept

Turns unattended mode on (default false).

agentBridge.autoAcceptFrom

Apps allowed to be auto-accepted. ["*"] means any linked app.

agentBridge.autoAcceptTimeoutMinutes

How long to wait for a reply before moving to the next request (default 30).

For truly hands-free operation

  • VS Code still asks before the chat runs tools such as editing files, running commands and bridge_send_reply. Approve them with Always Allow, or configure auto-approval in VS Code settings (search for autoApprove).
  • Restrict autoAcceptFrom to apps you own.
Heads-up: in unattended mode, text written by another agent drives an agent that can modify this workspace. Only enable it between apps you trust.
Security

Private by design.

The node is yours. It runs on your Mac and is reached only by machines you link. There is no cloud service in between.

🔒

Encrypted transport

HTTPS with a self-signed certificate created at install time. Clients pin its SHA-256 fingerprint, so they cannot be redirected to an impostor.

🎟️

Hashed, revocable tokens

The node stores only a hash of each machine's 256-bit token. Revoking a machine also closes its open streams.

🏠

Local-only dashboard

The dashboard listens on 127.0.0.1 and rejects foreign hosts and cross-site requests.

✋

Human in the loop

Requests require an explicit Accept unless you turn on unattended mode for that workspace.

📏

Bounded input

App names, subjects and bodies are validated and size-limited (512 KB per message).

✅

Signed and notarized

The app, the CLI and the binary inside the extension are signed with a Developer ID and notarized by Apple.

Command line

Prefer the terminal?

The same binary is a full CLI. Download it for macOS, Linux x64 or Linux arm64 (static, no dependencies), or use the one inside the app at /Applications/DAFO Agent Bridge.app/Contents/MacOS/agent-bridge.

On the node

# install as a login service
agent-bridge install --port 7878 --admin-port 7879
# machine tokens
agent-bridge device add "Build server"
agent-bridge device list
agent-bridge device revoke <id>
# open the dashboard / remove the service
agent-bridge dashboard
agent-bridge uninstall [--purge]

On any machine

# link this machine (token read from stdin)
agent-bridge pair --address 10.8.0.5:7878
agent-bridge client-status
# used by the extension
agent-bridge mcp --app billing-api
agent-bridge watch --app billing-api
# run a node in the foreground
agent-bridge init --bind 0.0.0.0:7878 --admin-bind 127.0.0.1:7879
agent-bridge serve

Requirements

  • Node: macOS 12 or later (Apple Silicon or Intel).
  • Extension: VS Code 1.101 or later with GitHub Copilot Chat in agent mode. Runs on macOS and Linux x64/arm64, locally or through Remote-SSH, WSL and dev containers. Windows is not supported yet.
  • Network: every linked machine must reach the node's IP and port (LAN or VPN).
